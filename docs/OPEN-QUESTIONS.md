実装に入る前に決めておきたい論点。優先度は以下の 3 段階。

- **P0**: 最初の PR（M0-1）をブロックする。今すぐ決めたい
- **P1**: v0.1 の途中までに決めたい。後から変えると手戻りが大きい
- **P2**: v0.3 以降で決めればよい

決まった項目は「決定」欄に記入し、根拠を `docs/adr/` に ADR として残す。

## 確定した決定事項（2026-09-04 / v0.6・v0.7 の計画時）

v0.5 到達後に他ライブラリ（Graphillion / TdZdd / SAPPOROBDD / CUDD+EXTRA）と機能を突き合わせ、
欠落を [docs/design/m6-api-expansion.md](design/m6-api-expansion.md) と
[docs/design/m7-directed-graphs.md](design/m7-directed-graphs.md) にまとめた際の決定。

| # | 論点 | 決定 | 根拠 |
|---|---|---|---|
| **D8** | **有向グラフを扱うか** | **扱う（M7 / v0.7）**。逆平行辺 `u→v` と `v→u` は許可、自己ループと多重辺は無向側と揃えて拒否。混合グラフは対象外 | D1（主用途 = 経路列挙）に対して、一方通行のある道路網・依存関係グラフが原理的に書けないのは「機能不足」ではなく「主用途の半分が欠けている」に近い。Graphillion も無向専用なので互換性のために我慢する理由が無い |
| **D9** | v1.0（API 凍結）の前に機能追加を挟むか | **挟む**。従来の M6「安定化と公開」を M8 に繰り下げ、M6（API 拡充）・M7（有向）を前に置く | 凍結後に足すと破壊的変更になるものだけを選んで前倒しした。性能改善・新出力形式など「後からでも足せるもの」は意図的に外している |
| **B17** | 項目写像（`MapItems`）の意味論 | **単射のみ許可**。重複があれば `ArgumentException`。support 外の要素の写像先は検査しない | 非単射写像は射影・存在量化であり、`{a},{b}` が `{x},{x}` に潰れて多重度が失われる。集合の族としての意味が変わるので別 API にすべき |
| **B18** | ユニバースが違う `SetSet<T>` 同士の演算 | **暗黙昇格はしない**。明示的な `ToUniverse(target)` を用意し、例外メッセージでそれを案内する | 暗黙に `ZddManager` を新規作成するとメモリ使用量が予測不能になる |
| **B19** | 変数数を後から増やす手段（B7 の再検討） | **B7（固定）は維持**したうえで、`TransferTo(largerManager)` を回避策として提供する | 一意化表の再構築を伴う動的追加は複雑さに見合わない。大きいマネージャを作って移す形なら既存の不変条件を壊さない |
| **B20** | `EnumerateInto` のバッファ長 | `MaxSetSize` 以上を要求し、不足なら `ArgumentException` | 切り詰めて黙って壊れるのが最悪。`MaxSetSize` は新しい `IDdEval<int>` として 30 行程度で足せる |
| **B21** | `TryBuild` が `false` を返す条件 | **`BuildLimit` 超過のときだけ**。キャンセルとスペック自身の例外は飲み込まない。`false` のときマネージャの状態は不変 | .NET の慣行では `Try` パターンはキャンセルを飲み込まない。状態不変は「トップダウン展開中は一時ノード表にしか書かない」ことから成立する |
| **B22** | `GraphSet` と `DirectedGraphSet` の共通化 | **共通基底クラスは作らない**。どちらも `SetSet<T>` の上に載る薄いラッパにする | 「`Including` が自分自身の型を返す」ために自己参照型引数（CRTP）が必要になり、公開 API の可読性が大きく落ちる。重複するのは各 30 行程度のラッパだけ |

## E. 決定が要らない（このまま進める）事項

念のため明示しておく。異論があれば指摘してほしい。

- ノード ID は `int`（2^31 ノード上限、約 32 GB）。64bit 版は作らない
- 一意化表・状態表は自前のオープンアドレス法（`Dictionary` は使わない）
- 家族代数演算は**すべて反復実装**（再帰禁止）
- 演算キャッシュは lossy direct-mapped（衝突は上書き）
- 参照カウントは実装しない
- 参考 OSS のコードはコピーせず、論文・ドキュメントから再実装する
- テストは xUnit ＋ CsCheck（プロパティテスト）＋ 総当たり照合
