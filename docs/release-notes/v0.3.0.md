# v0.3.0 リリースノート（2026-09-03）

M3「数千辺への対応と高レベル API」マイルストーン（[docs/PLAN.md](../PLAN.md) §12）の完了リリース。
ROADMAP の受け入れ条件「**数千辺の実グラフで経路数え上げが完走する**」を実データ規模で確認し
（[docs/benchmarks.md](../benchmarks.md) の M3-11 節）、機能面の中核が揃った。M4 以降は
性能改善・スペック拡充・パッケージング整備が中心になる。

## ハイライト

- **数千辺への対応**が中心テーマ。辺順序の自動最適化（`Graph.Optimize`。BFS/DFS/格子専用/
  ビームサーチの 4 戦略）と構築前の見積り（`Graph.EstimateMaxFrontierSize`）、フロンティア状態の
  bit-packing（メモリ 64〜65% 削減）を実装し、数千〜数万辺の実データ規模で s–t パス数え上げが
  完走することを実測で確認した（疎な道路網は 4 万辺超でも数秒で完走。密な道路網では幅が狭くても
  完走しない境界も正直に記録——docs/benchmarks.md M3-11 節）
- **高レベル API**: Graphillion 相当の `GraphSet`（生成・フィルタ・遅延列挙）と、任意の要素型を
  扱える `SetSet<T>` を追加。「格子グラフの s–t パスを数える」から「実グラフを読み込んで解く」
  までを一直線に辿れる `docs/tutorial.md` を新設
- **グラフ入出力**（`ZDD.Net.Io`）: DIMACS / エッジリスト / 本ライブラリ独自の簡易テキスト形式の
  読み書き。実データファイルをそのまま `Graph` として読み込める
- **スペックの拡充**: サイクル・ハミルトンパス／サイクル、頂点系スペック（独立集合・クリーク・
  頂点被覆・支配集合）、次数制約、そして 2 つのスペックを中間結果を経由せず直接合成する
  `And`/`Or`/`Subset`
- API はプレリリース扱いで、v1.0 までは破壊的変更があり得る

## 既知の制約

- 辺順序最適化のビームサーチ（`BeamSearchPathWidth`）は「主要ベンチで 20% 以上改善」を条件に
  検証しているが、格子のように既に良い順序のグラフでは伸びしろが薄い（改善しないケースも
  docs/benchmarks.md に正直に記載してある）
- フロンティア幅の見積り（`EstimateMaxFrontierSize`）が狭くても、迂回路の多いグラフでは
  実際の状態数が指数的に膨らみ完走しないことがある（docs/benchmarks.md M3-11 節、
  docs/tutorial.md §4「幅が大きすぎるときにどうするか」）
- `IHybridDdSpec<TScalar>`（スカラ + `int` 配列の複合状態）は契約のみで、
  `FrontierBuilder.Build` のオーバーロードは未対応
- API はプレリリース扱いで、v1.0 まで破壊的変更があり得る
