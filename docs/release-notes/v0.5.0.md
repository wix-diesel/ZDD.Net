# v0.5.0 リリースノート（2026-09-04）

M5「I/O・メモリ管理」マイルストーン（[docs/PLAN.md](../PLAN.md) §12）の完了リリース。独自
バイナリ形式・Graphillion 互換テキスト形式によるシリアライズ、mark & sweep 方式のノード GC、
DOT 出力の拡張、CLI サンプルの拡充、DocFX による API ドキュメントサイトの公開をもって機能面が
出揃った。**v1.0 に持っていく前の最後の機能追加リリース**であり、次の M6 は API 凍結・AOT 検証・
パッケージング・チュートリアルという「公開の準備」だけを残す。

## ハイライト

- **シリアライズ 2 形式を追加**。`ZDD.Net.Io.ZddBinaryFormat` は独自バイナリ形式で、構築よりも
  1〜2 桁速く保存・復元できる（フレッシュなマネージャへの読み込みならノード ID まで含めて元の族と
  一致する）。`ZDD.Net.Io.GraphillionTextFormat` は Python Graphillion の
  `setset.dump`/`dumps`/`load`/`loads` 互換のテキスト形式で、実際に Graphillion 2.1 をインストール
  して生成した出力を読み込んで結果が一致することを確認済み。どちらも壊れた入力は
  `ZddFormatException` になり、本体 `PackageReference` は引き続き 0
- **ノード GC**（`ZddManager.Collect()` / `RootSet`）。参照カウントではなく明示 GC 方式にし、
  `RootSet` に登録した族だけが GC を生き延びる。登録していない古いハンドルを GC 後に使うと
  `ZddCollectedException` になり、黙って壊れた結果を返さない。mark は反復実装なので、変数
  10 万本の深い ZDD でもスタックオーバーフローしない
- **DOT 出力の拡張**（`DotOptions`）。状態ラベル・レベルラベル・部分表示（`MaxLevels` /
  `MaxNodes` / `FocusNodeId`）・スタイルのカスタマイズに対応。既定は今までの `ToDot()` と完全に
  同じ出力
- **`samples/Zdd.Cli` にサブコマンドを追加**: `grid-path` / `spanning-tree` / `partition` /
  `matching`。共通オプション（`--edge-order` / `--progress` / `--dot` / `--estimate` /
  `--save`/`--load` / `--sample` / `--min-weight`）でグラフ系スペックをそのまま叩ける
- **API ドキュメントサイトを公開**（<https://wix-diesel.github.io/ZDD.Net/>）。DocFX が手書き
  ガイドと XML doc から全 public API のリファレンスを生成し、main への push ごとに再公開する
- API はプレリリース扱いで、v1.0 までは破壊的変更があり得る

## v1.0 に向けた API レビューの下準備

M5-7 では、public API の一覧を棚卸しし、命名・一貫性の気になる箇所を
[docs/api-review-notes.md](../api-review-notes.md) にまとめた。実際の凍結・命名変更は
M6-1（issue #60）で行う。現時点で `[Experimental]` を付けている public API は無いが、
`IHybridDdSpec<TScalar>`（`FrontierBuilder.Build` が未対応のため事実上使用できない契約のみの
公開型）については M6-1 での判断（実装するか、`[Experimental]` を付けるか、internal に戻すか）を
推奨事項として引き継ぐ。

## 既知の制約

- `IHybridDdSpec<TScalar>`（スカラ + `int` 配列の複合状態）は契約のみで、
  `FrontierBuilder.Build` のオーバーロードは未対応（M2 からの既知の制約が継続）
- `Zdd` の `Restrict`/`Permit`/`OnSet`/`Subset1`/`OffSet`/`Subset0` のように、SAPPOROBDD 由来の
  名前と .NET 的な別名が両方 public API として残っている箇所がある。M6-1 でどちらを正とするか
  決める（詳細は docs/api-review-notes.md）
- API はプレリリース扱いで、v1.0 まで破壊的変更があり得る
